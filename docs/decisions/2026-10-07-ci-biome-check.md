# CI と Biome と `pnpm check`: 揺れを機械で止める（2026-10-07、0.5.2）

- 日付: 2026-10-07
- 状態: 採用（react-doctor / fallow は不採用）
- 出自: HANDOFF.md 旧 §10（2026-10-07 に 1 判断 1 ファイルへ分割。本文は当時のまま）

- 背景: 2026-10-07 の棚卸しで「出力の揺れを人の注意ではなく機械で止める仕組みが無い」が最大の不足だった（CI 無し、フォーマッタ無し。`reporter.ts` に `biome-ignore` コメントがあるのに Biome の設定が無い状態）。一方で、会社のアプリは GitHub Actions を使えない前提。**基盤リポジトリには GitHub Actions、アプリ（雛形）には `pnpm check`** と分けた。資産は YAML ではなく、中で呼ぶコマンドのほう
- **`.github/workflows/ci.yml`**: 3 ジョブ。`node`（ubuntu: `pnpm gen:check` → `pnpm lint` → `pnpm -r typecheck` → Chromium を入れて `pnpm -r test` → `pnpm build` して `git diff --exit-code -- packages/gen/vb-runtime packages/gen/template` で同梱コピーの同期を検証。失敗時は test-results を artifact に）、`dotnet-linux`（Contract のビルドと Contract.Tests。Mac で通している範囲と同じ）、`dotnet-windows`（`WebView2Bridge.sln` 全体。Mac では確かめられない WinForms / net48 の Windows ビルドを機械で）。api / host（実 exe + WebView2 + DB）は CI で走らせない。トリガは全ブランチの push と workflow_dispatch（`pull_request` を足すと同じコミットが二重に走るので使わない。ソロ運用）。`concurrency` で同じブランチの古い実行は打ち切る
- **Biome 2.5**（`biome.json` 1 枚、`@biomejs/biome` は root の devDependency。postinstall スクリプトが無いので `allowBuilds` は不要）。書式: 2 スペース、幅 120（既存 TS 約 6,600 行のうち 120 以内が 96%。Prettier 既定の 80 では差分が大きすぎ、140 では揃える意味が薄い）、ダブルクォート、セミコロン、末尾カンマ all。import の並び替えは assist の organizeImports。lint は `preset: "recommended"`（`recommended: true` は 2.5 で非推奨）に対し 3 つだけ切った: `complexity/useLiteralKeys`（`Record` の動的キーは `obj["key"]` と書く習慣を保つ。68 件）、`style/noNonNullAssertion`（`noUncheckedIndexedAccess` の下で `!` は意図的。46 件）、`style/useTemplate`（`out.join("\n") + "\n"` のほうが読みやすい。9 件）。対象外: `**/generated`、`contract.schema.json`、`openapi.json`、`packages/gen/template`、`packages/gen/vb-runtime`（生成物と同梱コピーは触らない）、`.gitignore` の内容（`vcs.useIgnoreFile`）
- 初回適用で直したもの: 20 ファイルの整形、未使用 import 1（memory.test.ts）、`forEach` のコールバックが値を返す 2（http.ts、emit-openapi.test.ts）、`while` 条件内の代入 1（http.ts の SSE 行分割）、Playwright フィクスチャの `async ({}, use)` に `biome-ignore`（第 1 引数は分割代入でなければ Playwright が受け付けない）、`App.tsx` の events ログの `key={i}` を連番 id に（react-doctor も同じ指摘をした）、雛形 `main.tsx` の `<button>` に `type="button"`
- **雛形**: `biome.json` を `templates/myapp/_biome.json` の名前で持つ。`templates/myapp/biome.json` と置くと本体の `pnpm lint` が「Found a nested root configuration」で止まるため（Biome 2 は入れ子の設定に `root: false` を要求するが、雛形は書き出した先では唯一のルート）。`_gitignore` / `_npmrc` と同じ仕組みで init の `BUNDLED_RESTORE` が `biome.json` に戻す（`init.test.ts` で検証）。雛形の設定は本体と同じ書式・同じ規則（除外は `generated` / `contract.schema.json` / `openapi.json` / `dist` / `test-results` / `playwright-report` / `bin` / `obj`。`vcs` は使わない。`pnpm create` 直後は git リポジトリでないことがあるため）。scripts に `lint` / `lint:fix` / `typecheck` / `check`（`gen:check → lint → typecheck → test`）。README の「日々のループ」に `pnpm check` を足した。pre-push フック（lefthook 等）は雛形に入れない: 依存とビルドスクリプト許可が増えるので、要るアプリが自分で足す
- `.vscode/settings.json`（保存時に Biome で整形）と `extensions.json` を追加。Mac と会社 PC と AI セッションで同じ書式になる
- **react-doctor / fallow は採用しない（実測の記録）**: react-doctor は診断はローカル（apps/web 13 ファイル 2 秒）だが 0〜100 のスコアは外部 API が計算する（この環境では 403 で「Score unavailable」。`--no-score` フラグがある）。外に出られない会社 PC では点数が取れないので「点数を保つ」運用は成立しない。診断 2 件のうち `effect-needs-cleanup` は誤検知（`return client.events.on(...)` が購読解除関数を返している）、`no-array-index-as-key` は妥当（上で直した）。fallow は完全ローカルで決定的、`--format json` / baseline / `fix` を持ち、`health --score` 82 点 B、全項目 66 点 C。ただし減点の半分近くは設定不足の雑音（`templates/myapp` を未使用ファイル、生成物の `MethodMap` 等を未使用 export、knex に文字列で渡す `better-sqlite3` を未使用依存と判定）。本物の信号は `emit-vb.ts` の `resolveType`（循環的複雑度 26）、`db/env.ts` の `knexConfigFromEnv`（26）、`emit-ts.ts` の `visit`（21）で、分割の候補。採用するなら `.fallowrc.json`（entry point と除外）→ `--save-baseline` → 「基準より下げない」の順で、固定の 90 点は追わない。今は Biome だけで始める
- 版: 雛形を変えたので gen を 0.5.2 にした（RELEASING 手順 1。npm 4 つ、`WebView2BridgeVersion`、雛形の依存 `^0.5.2`、`pnpm gen:template` でランタイムのヘッダを 0.5.2 に）。**公開はユーザーが行う**
- **初回 CI で見つかった環境差（Node 22.23.3）**: gen のテスト 4 件（`generate.test.ts` 3 件、`init.test.ts` の「雛形の生成物が最新」）が `Cannot find module '.../node_modules/.pnpm/zod@4.5.4/node_modules/zod/index.cjs?namespace=...'` で落ちた。テストが契約を `os.tmpdir()` に書き、その `import { z } from "zod"` を tsx が親モジュール側へフォールバックして CJS の `index.cjs` で解決する経路が、Node 22.23 の tsx（sync resolve hooks）で壊れる。手元の 22.22.0 では通る。実アプリの経路（契約が自分の node_modules を遡って ESM の `index.js` を解く）は同じ CI の `pnpm gen:check` で通っているので、製品側の問題ではない。対処: テスト用の一時ディレクトリをパッケージ内 `packages/gen/.tmp/`（git 管理外）に移す `mkTempDirInPackage` を `test/fixtures.ts` に置き、bare import が実アプリと同じ経路で解決されるようにした。契約の置き場をテストだけ特別扱いしていたのが原因で、テストのほうを現実に寄せた
