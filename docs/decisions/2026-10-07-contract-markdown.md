# 契約の仕様書 `contract.md` を gen が生成する

- 日付: 2026-10-07
- 状態: 採用
- 出自: 2026-10-07 の作業で追加

- 背景: 契約の説明は `.describe()` が VB の XML doc、TS のコメント、OpenAPI の summary に流れていたが、人と AI が読む 1 枚の文書が無かった。棚卸し（2026-10-07）で「仕様書・説明書が用意できる」が目標の 1 つだったので足した
- `packages/gen/src/emit-markdown.ts`。設定 `markdown.out`（例 `contract/contract.md`）を書くと生成する。省略時は出さない。オプションは `title` / `basePath` / `eventsPath`（`openapi` と揃える）。root と雛形の `webview2-bridge.gen.json` に追加した
- 内容: メソッド一覧 → 名前空間ごとにメソッド（呼び出し方を JSON-RPC / HTTP / TypeScript / VB.NET の 4 行で、入力と出力の項目表）→ イベント → 共有型（`.meta({ id })`。列挙は値の一覧）→ エラーコード表（JSON-RPC と HTTP の対応、いつ起きるか）→ 型の対応表（zod / JSON Schema / TS / VB）。型名は VB の DTO 名と TS の型名を併記する
- 無名の入れ子 object は別の型に起こさず、`address.line1` / `children[].childId` / `attributes.*.x` のように経路で平らに並べる（表が読みやすく、VB の `<親><項目>` 命名を知らなくても追える）。`.describe()` は説明列に出る
- zod 4 の `.int()` が付ける `minimum / maximum = ±MAX_SAFE_INTEGER` は契約の意図ではないので表示しない。`z.unknown()` は zod の JSON Schema では `required` に入る（TS の型も zod 4 では必須キー）ので「必須」と出る
- 先頭は `<!-- <auto-generated> ... -->`。gen の「auto-generated ヘッダの付いた古い生成物だけ消す」規則がそのまま使える（同じディレクトリの手書き `.md` は消えない）
- AI チャットに渡す最小セットは `contract.ts` + `contract.md` + `e2e/` + `Impl/`。生成コードとランタイムを含めなくてもアプリの仕様と振る舞いが説明できる（slnmix のパックもこの単位に寄せる）
- テスト: `emit-markdown.test.ts`（スナップショット 2 件 + 項目表・経路・列挙・null 許容・共有型参照の検証）。`generate.test.ts` に出力 1 件を追加
