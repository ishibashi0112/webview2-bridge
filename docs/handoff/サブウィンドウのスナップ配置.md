# サブウィンドウのスナップ配置（複数ウィンドウ）— 検討メモ（2026-10-25、未実装）

Windows 11 のスナップレイアウト（最大化ボタンにマウスを乗せると出る配置グリッド）のように、**Web アプリの画面から別の画面を別ウィンドウで開き、PC のスクリーン上に左右 / 四隅へ並べる**機能を、この基盤のオプションとして足す案。
HANDOFF.md §10 の決定事項に要約があり、ここはその背景と設計の詳細。決めたことは既定値で、変えたければ変える。

## 1. 背景

- 発端（2026-10-25、作るもの探しプロジェクトのスレッド「画面分割サブウィンドウの React ライブラリ調査」）: 「業務システムの 2 つの画面を PC に左右で並べる」ことを Web アプリ側から簡潔にやりたい。
- 調査の結論:
  - **ページ内**の分割・ドッキング（VS Code 風のタブ・分割・フローティング）は既製で足りる: [dockview](https://dockview.dev/)（別ブラウザウィンドウへのポップアウトもある）、[rc-dock](https://www.npmjs.com/package/rc-dock)、[flexlayout-react](https://github.com/caplin/FlexLayout)、単純な分割なら [react-resizable-panels](https://github.com/bvaughn/react-resizable-panels) / [allotment](https://github.com/johnwalley/allotment)。作る余地は無い
  - **本物のウィンドウをスクリーン上に配置する** React ライブラリは見当たらない。部品はある: [react-new-window](https://github.com/STRML/react-new-window)（`window.open` した窓に Portal 描画）、[Window Management API](https://web.dev/articles/web-apps/multiple-screens)（マルチモニタの座標。Chrome / Edge 100 以降のみ、許可ダイアログあり）、[Document Picture-in-Picture](https://blog.logrocket.com/using-chrome-document-picture-in-picture-api-react)（常に最前面の小窓。Chrome 116 以降）
  - ブラウザだけでも `window.open(url, name, "popup,left=…,top=…,width=…,height=…")` で別の OS ウィンドウとして位置指定で開ける（ユーザー操作の中で呼ぶこと）。ただし **今見ているタブ自身は動かせない**（動かせるのは `window.open` で開いた窓だけ）、マルチモニタは Window Management API が要る、ポップアップブロックの対象、という制約がある。Chrome 自体のタブ分割（Split View）は利用者の手動操作で、ページからは発火できない
  - **WebView2 ではホスト（WinForms）が窓の持ち主なので、この制約が消える**（ポップアップブロック無し、許可ダイアログ無し、`Screen.AllScreens`、メインウィンドウも動かせる）。実装の価値はブラウザ版より WebView2 版にある
- この基盤の現状: `NewWindowRequested` は http(s) を既定のブラウザへ渡し、それ以外は止める（HANDOFF.md §10「SBOM 移行の改善提案 P1」）。理由は、既定のままだとブリッジの無い素の WebView2 窓が開いて役に立たないから。つまり **2 つ目の画面を正しく開く手段が今は無い**。一方、SBOM は画面ごとに別ウィンドウを開いていて、packages/test には `hostWindows` / `waitForWindow`（C-2）が既にある。需要は手元にある
- 進め方の判断: 先にライブラリとして切り出さず、**この基盤のオプションとして作り、SBOM で使ってから**切り出すかを決める（ライブラリとしての需要は狭く、ブラウザ版は数十行で済むため）

## 2. 狙い（HANDOFF.md §2 に照らして）

- **画面側のコードはブラウザと WebView2 で共通にする。** 画面は標準の `window.open(url, name, features)` を呼ぶだけ。ブラウザ単体（MemoryTransport）の開発と screen テストでも同じコードが本物のポップアップを開く。Host は `NewWindowRequested` の `WindowFeatures` に届く位置・大きさを Form に写すだけ
- **VB の手書きは増やさない。** WinForms ランタイムにクラスを 1 つ足し、MainForm は 1 行で有効化する
- **あくまでオプション（opt-in）。** 雛形でも既存アプリでも既定は無効で、使うアプリだけが MainForm で有効にする。既定の動き（外部 URL はブラウザへ、それ以外は止める）は変えない（2026-10-25 の判断）

## 3. 形（既定値）

### 3.1 Host: WinForms ランタイムに `BridgeWindows`（仮名）

- 生成: `New BridgeWindows(env, dispatcher, ownerForm)`。`Attach(core)` で `NewWindowRequested` を購読する（MainForm の `Core_NewWindowRequested` を置き換える）
- 振り分け: `e.Uri` が **自アプリの URL**（`https://app.local/…`、または Debug で dev サーバーに接続中ならその URL）→ 新しいウィンドウを作る。それ以外の http(s) → 今まで通り既定のブラウザ。その他 → 止める
- 作り方: `Dim deferral = e.GetDeferral()` → 新しい `Form`（WebView2 を `Dock = Fill`）→ `Await webView.EnsureCoreWebView2Async(env)`（**同じ `CoreWebView2Environment`** = 同じユーザーデータ。`SetVirtualHostNameToFolderMapping` は CoreWebView2 ごとなので新しい core にも掛ける）→ `Settings`（`AreDevToolsEnabled` / `AreBrowserAcceleratorKeysEnabled` は MainForm と同じく DevMode 連動）→ `New WebViewBridge(webView, dispatcher).Attach()`（**Dispatcher は WebView2 非依存なので共有**。`Register` と `MissingMethods` は MainForm の 1 回でよい）→ `e.NewWindow = webView.CoreWebView2` → `e.Handled = True` → `deferral.Complete()`。`e.NewWindow` に渡すと Navigate は WebView2 が行い、`window.opener` と `window.open` の戻り値（WindowProxy）が成立する（開いた側から `close()` / `focus()` できる）
- 位置と大きさ: `e.WindowFeatures`（`HasPosition` / `HasSize` / `Left` / `Top` / `Width` / `Height`）を `StartPosition = Manual` + `Bounds` に写す。無ければ開いた側の Form と同じ大きさで少しずらす。**DPI に注意**: features は CSS px、`Bounds` は物理 px。開いた側の `DeviceDpi / 96`（または WebView2 の `DeviceScaleFactor`）を掛ける。会社 PC の 125% / 150% で確認する項目
- はみ出し: `Screen.FromPoint` の `WorkingArea` に収める（スクリーン外に出たら詰める）
- 寿命: 子ウィンドウは `BridgeWindows` が一覧で持ち、MainForm の `FormClosing` で全部閉じる。`Owner` は設定しない（Owner にすると常に親の前に出て、左右に並べる用途に合わない）
- イベント（Host → Web 通知）: 今の `BridgeEvents(emitter)` は 1 つの `WebViewBridge` を受け取る。複数窓では **全窓に同報する `IBridgeEmitter`**（`BroadcastEmitter`、仮名。登録済みの WebViewBridge 全部に `Emit`、閉じた窓は外す）を `BridgeWindows` が持ち、MainForm は `New BridgeEvents(windows.Emitter)` にする。窓を選んで送りたくなったら、要求がどの WebViewBridge から来たかを Dispatcher に渡す拡張で足りる（初期スコープ外）
- マルチモニタ: v1 は Web 側が **自分のモニタ**で座標を出す（`window.screen.availLeft / availTop / availWidth / availHeight`。Chromium では開いた側の画面の作業領域）。別のモニタに置くのは v2: 契約に `app.screens`（`Screen.AllScreens` を返す）を足すか、WebView2 の `PermissionRequested` で Window Management を許可して Web 標準の `getScreenDetails()` を使う（SDK にその `PermissionKind` があるか要確認）
- **自分自身を動かす**（「自分を左に、相手を右に」）: ブラウザでは不可能だが、WebView2 では Host が MainForm を動かせる。契約に `app.snapSelf({ slot })` を足せばよい。v2

### 3.2 Web 側

- 画面は標準の `window.open(url, name, features)` を使う。小さなヘルパ `openScreen(route, { slot, name })` を用意する: `slot`（`"left" | "right" | "top-left" | "top-right" | "bottom-left" | "bottom-right" | "full"`）→ `window.screen.avail*` を 2 分割 / 4 分割 → `"popup,left=…,top=…,width=…,height=…"`。`name` を固定すると同じ画面は同じ窓に出る（`window.open` の仕様）。戻り値の WindowProxy を持てば `close()` / `focus()` できる。まず `apps/web/src/windows.ts` に置き、固まったら client のサブパス（`@ishibashi0112/webview2-bridge-client/windows`）に切り出す
- スナップ風のグリッド UI（2 分割 / 3 分割 / 4 分割の絵から枠を選ぶ）は React 部品 `SnapPicker`（仮名）。まず apps/web の見本画面に置く
- ブラウザ（MemoryTransport）では同じ `window.open` が本物のポップアップを開く。ユーザー操作（click）の中で呼ぶ
- 窓の間の状態共有: 同じ origin なので `BroadcastChannel` が使えるが、業務の正しさは Host 経由（契約メソッド + イベント同報）に置く（CLAUDE.md「localStorage 等は使わない」「業務の正しさをイベントに依存させない」に従う）

### 3.3 テスト

- screen: 新しい窓は Playwright の `context` に新しい `Page` として現れる → 既存の `waitForWindow`。host: 新しい WebView2 は同じ BrowserContext の新しい Page（C-2 で確認済み）。api: 変わらない
- **Windows 実機で確認する項目**: (1) `e.NewWindow` 方式で窓が開き `window.opener` が取れる、(2) features の位置が 100% / 125% / 150% で合う、(3) 子窓から契約メソッドが呼べ、イベントが両方の窓に届く、(4) MainForm を閉じると子窓も閉じる、(5) 外部 http(s) は今まで通りブラウザへ行く、(6) Release で子窓でも F12 / F5 が効かない、(7) `name` 固定で同じ窓が再利用される

### 3.4 版と公開

- 破壊的変更なし。WinForms ランタイムにクラスが増える（gen 同梱 → `sync:vb-runtime`）。**雛形でも既定は無効（opt-in）**: 雛形の MainForm は今の `Core_NewWindowRequested` のままにし、`BridgeWindows` に置き換える形をコメント（と雛形 README）で示す。使うアプリだけが置き換える。既存アプリも同じ（`pnpm gen` でランタイムを更新してから置き換える）→ **0.7.0（マイナー）**

## 4. やらないこと

- ページ内の分割・ドッキング（dockview 等で足りる。必要な画面で採用すればよい）
- 先にライブラリとして切り出すこと（SBOM で使ってから）
- Electron / Tauri 対応（§2「ホストは差し替え可能」の範囲で、Web 側が `window.open` のまま動くことだけ守る）

## 5. 進め方

- **A**: WinForms ランタイムに `BridgeWindows` + `BroadcastEmitter`、本体 apps/web に `openScreen` と見本ボタン（左 / 右）。Linux で `dotnet build`、Windows で 3.3 の確認
- **B**: 雛形に opt-in の形で入れる（MainForm に有効化の手順をコメントで、雛形 README に説明、`e2e/screen` に「窓が開く」テストは本体の見本に置く）。0.7.0 として公開
- **C**: SBOM に入れて使う。使い心地が固まったら `SnapPicker` と `openScreen` を client のサブパスへ切り出す
